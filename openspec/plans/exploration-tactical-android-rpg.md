# Исследование: тактическая пошаговая RPG для Android

## Контекст

Проект OpenSpec (schema `spec-driven`) стартует с чистого состояния — [`specs/spec.md`](../specs/spec.md) пуст, активных изменений нет. Это первый концепт-эксплор для будущих change-предложений.

## Идея

Однопользовательская игра для Android: тактические пошаговые бои на сетке с разными классами персонажей, открытый мир с несколькими сюжетными кампаниями, отряд 3–4 героя, 2D-графика (векторная / псевдо-3D). Важное требование — удобная портируемость на другие платформы.

## Принятые решения (в рамках эксплора)

| Вопрос | Решение | Обоснование / оговорки |
|---|---|---|
| Формат боя | Тактический на сетке (XCOM / FF Tactics) | Позиционирование и классы игрока имеют механический смысл |
| Стек | Кандидат: **Godot 4** | Кросс-платформенность (Android/iOS/Desktop/Web) из коробки, лёгкий для 2D, открытый исходный код. Альтернативы: Unity (C#, крупная экосистема), LibGDX (Kotlin/Java, полный контроль, но больше ручной работы) |
| Структура мира | Открытый мир + несколько сюжетных кампаний | Самая амбициозная часть; требует контент-пайплайна (карты, диалоги, триггеры кампаний) |
| Отряд / стиль | 3–4 героя, 2D векторная / псевдо-3D | Изометрия или billboard-спрайты на псевдо-3D карте — типичный компромисс |

## Ключевые подсистемы (для декомпозиции)

1. **Боевая система** — сетка, очередь ходов (initiative), зона видимости/наведение, классы и их способности, ИИ противников.
2. **Классы персонажей** — данные классов (статы, способности, деревья развития), баланс.
3. **Открытый мир** — карта мира, перемещение, точки интереса, encounters.
4. **Кампания/сюжет** — квестовая система, диалоги, флаги прогресса, несколько кампаний.
5. **Прогрессия** — опыт, уровни, снаряжение, инвентарь.
6. **Платформенный слой** — save/load, управление (тач + опционально геймпад), локализация, стор-сборка.

## Риски

- **Масштаб открытого мира** — главный риск; рекомендуется фазирование: сначала вертикальный срез (1 бой + 1 класс противника + мини-карта), затем одна короткая кампания, потом «открытость».
- **Контент-объём нескольких кампаний** — без редактора/дата-пайплайна контент не масштабируется; данные кампаний стоит проектировать как декларативные ресурсы.
- **Портируемость** — зафиксировать стек на раннем этапе, избегать платформо-зависимых плагинов в ядре геймплея.

## Предложенный первый change-предложение (кандидат)

`add-vertical-slice` — минимальный играбельный вертикальный срез:
- одна сетка боя, 2 класса героя, 1 тип врага, очередь ходов, победа/поражение;
- технический стек-скелет (Godot 4, структура проекта, save/load-заглушка);
- критерии: бой играется на устройстве Android за 3–5 минут, инпут только тач.

## Следующий шаг

Создать change-предложение (`/opsx:new add-vertical-slice`) на базе этого эксплора.
