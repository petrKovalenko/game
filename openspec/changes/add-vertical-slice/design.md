# Design: add-vertical-slice

## Context

Вертикальный срез — первый код проекта. Требования: только тач-ввод, кросс-платформенность, декларативные данные юнитов (см. [proposal](proposal.md) и [эксплор](../../plans/exploration-tactical-android-rpg.md)).

## Goals / Non-Goals

**Goals:**
- Играбельный бой на Android за минимальный объём кода.
- Архитектурные точки расширения: классы → новые классы; бой → новые карты/типы врагов.
- Никаких платформо-зависимых API в игровой логике.

**Non-Goals:**
- Открытый мир, кампании, save/load, инвентарь, прогрессия.
- Оптимизация под слабые устройства сверх разумного.

## Decisions

### D1. Движок: Godot 4 (GDScript)

- **Альтернативы**: Unity (тяжелее для старта, лицензионные нюансы), LibGDX (много ручной работы).
- **Выбор**: Godot 4 + GDScript — быстрый цикл итераций, экспорт Android/Desktop/Web из коробки, свободная лицензия.
- GDScript для геймплея; при росте производительности ядро боя можно вынести в C#-модуль — не в этом change.

### D2. Слой логики отделён от слоя представления

- Игровая логика боя (сетка, очередь, урон) — чистые скрипты без зависимости от Node-сцены; **Scene-нода — тонкий адаптер**.
- Обоснование: логика становится тестируемой (GDScript unit-тесты, GUT), и в будущем её можно переиспользовать на других сценах (мир,encounters).

### D3. Сетка: изометрические тайлы 2D, дискретные координаты

- Карта — тайловая, изометрический рендер (TileMapLayer) для «псевдо-3D» вида.
- Логическая сетка — `Vector2i`, перемещение — по клеткам, поиск пути — BFS/A* по проходимости.

### D4. Очередь ходов: инициатива

- Каждый юнит имеет `initiative`; порядок раунда — сортировка по инициативе (при равенстве — случайный, фиксированный seed на бой для воспроизводимости).
- Юнит имеет 1 действие и 1 перемещение за ход (классика тактики).

### D5. Данные юнитов: декларативные ресурсы

- Классы героев и враги описываются кастомными `Resource` (`.tres`): статы, способности, инициатива.
- Обоснование: заготовка контент-пайплайна для будущих кампаний; дизайн-контент правится без кода.

### D6. Тач-ввод

- Тап по клетке: контекстное действие (переместиться / выбрать цель).
- Панель способностей внизу экрана — крупные зоны нажатия (мин. 44 dp).
- Также поддерживается мышь на Desktop — единый обработчик `InputEventMouseButton/TouchScreenButton`.

## Risks / Trade-offs

- **Изометрия дороже ортогонали в UI-математике** — принимаем: читаемость сетки критична для тактики.
- **GDScript-тесты (GUT) требуют настройки** — принимаем ради тестируемости логики (D2).
- **Seed-фиксация** упрощает отладку, но бета-игроки получат одинаковую раскладку инициативы — приемлемо для среза.

## Open Questions

- Нужен ли индикатор зоны перемещения в реальном времени при тапе на героя (vs. только подсветка после выбора)? — решить при первом игротесте.
- Минимальная версия Android для целевого устройства — уточнить при настройке экспорта.

## Migration Plan

Не требуется (зелёное поле). Структура проекта сразу закладывается по слоям: `src/logic/`, `src/scenes/`, `src/data/`, `tests/`.
